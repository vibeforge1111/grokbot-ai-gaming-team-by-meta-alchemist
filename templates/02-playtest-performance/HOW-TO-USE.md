# How to use: Playtest and Performance Director

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- Collect worked examples from at least two real games, not only the synthetic pack.
- Ship or document a pack producer that writes artifact bytes and a producer receipt. This preview has no bundled Playwright runner or GPU sampler. The capture skills describe how to collect frame times and journeys. The owner, or the owner's own tools, still assembles the pack.
- Earn points from captured frame samples and journey traces. Today a pack can still declare some counts by hand (scenario tallies, seed counts, SHA flags).
- Confirm the single-device profile and the extra-device line against a real second device, not only the synthetic example.

Grade playtest journeys and frame time for any game, then write a local evidence pack and ticket drafts.

- **Pipeline stage:** Playtest.
- **When:** After a playable build can be clicked, tapped, or driven through its opening and a core session, and you want a first read of journeys and frame time.
- **You provide:** Your game profile (`game-profile`), journey traces or session notes, and frame-time samples from the devices you care about. Optional files from Game Feel (01), Game Loop (05), or HUD (09) can sit beside those captures.
- **You get:** A local evidence pack (`evidence-pack`), a 100-point grade (`grade-record`), and local ticket drafts (`ticket-draft`). Nothing is filed until you file it.
- **Takes from:** The owner's game profile, plus optional `feel-findings`, `loop-report`, and `hud-capture-set` when those bots have already run.
- **Hands to:** Other shipping templates that read an `evidence-pack`; Bug Desk (18) for ticket drafts; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option A: Add to Grok Bot after review

Share link coming soon. Use Option B for Grok Bot or Option C for other agents. Both work offline with the local files.

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." Start with the [`playtest-performance-lens-engine`](skills/playtest-performance-lens-engine/SKILL.md) skill, then the [`playtest-performance-getting-started`](skills/playtest-performance-getting-started/SKILL.md) skill, then `frame-pacing-and-gpu-profiler` and `autonomous-browser-playtest`.
2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the playtest-performance-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

### Option C: Other agents (Cursor, Claude Code, Codex)

Copy `skills/<name>/SKILL.md` into your agent's skills folder (for example `.cursor/skills/`, `.claude/skills/` or the folder your Codex setup reads). Copy `engine/` and `fixtures/` into your repo so the agent can run the engine, or let the agent write them from the `-lens-engine` skill. See [INSTALL.md](../../INSTALL.md).

## First grade in two minutes

```
cd templates/02-playtest-performance
node engine/lens.mjs fixtures/good-pack.json      # worked example (synthetic, not a measurement)
node tests/lens-negative-fixtures.mjs             # every negative and missing-input case must behave
node tests/test-lens-contract.mjs                 # rubric, recipe embed and text checks
node engine/lens.mjs your-pack.json               # your build
```

The synthetic example prints verdict **PASS** and grade **100/100**. It is not a measurement of any game.

## First real pack

1. Agree the profile with the getting-started skill, including the frame-time budget and whether a second device is in scope.
2. Collect journey traces and frame samples with the evidence skills, or with the owner's own capture tools. Keep each source file on disk under the pack's folder.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

This preview does not yet require a producer receipt. A later shipping version should check artifact bytes and a receipt. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- What the opening journey and the core journey are, in this game.
- Which viewports are required.
- The frame-time budget on the primary device. 16.67 ms is a common 60 Hz starting point. Do not assume a 90 fps target.
- Whether a second device profile is in scope. If it is not, approve the `single-device` rubric profile before scoring.
- Whether to set `profile.bands.minCases`. A line with fewer observed cases than that number reads U.
- Who reviews the local drafts. The bot never files them.

## Words used here

- **Opening journey:** the first session path a new player is meant to finish, from launch to the first meaningful activity.
- **Core journey:** the repeating session path you care about on this build, on each required viewport.
- **Frame-time budget:** the owner-set p95 time per frame, in milliseconds. The rubric does not assume a frame rate.
- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `feel-findings` (optional, ^1.0.0) | 01 Game Feel | `.grokbot-team/artifacts/feel-findings/` | Continue without it. Start the report with "ASSUMPTION: no feel-findings available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |
| `loop-report` (optional, ^1.0.0) | 05 Game Loop | `.grokbot-team/artifacts/loop-report/` | Continue without it. Start the report with "ASSUMPTION: no loop-report available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |
| `hud-capture-set` (optional, ^1.0.0) | 09 HUD | `.grokbot-team/artifacts/hud-capture-set/` | Continue without it. Start the report with "ASSUMPTION: no hud-capture-set available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `evidence-pack` 1.0.0 | JSON evidence pack plus a local manifest | `.grokbot-team/artifacts/evidence-pack/` | 01 Game Feel, 03 Prop and Rig, 05 Game Loop, 06 Economy, 09 HUD, 10 Trailer, 11 Environment, 12 Producer, 13 Audio, 14 NPC and Lore, 15 Server Fairness, 17 Sprites, 18 Bug Desk, 19 Store Page, 20 Patch Notes, 21 Access, 22 Live Service, 23 Support Desk, 24 Ledger, 25 Matchmaking, 26 Balance Patch, 27 Retention, 28 App Store, 00 Starter |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-02-playtest-performance` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
