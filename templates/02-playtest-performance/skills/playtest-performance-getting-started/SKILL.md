# Playtest and Performance Director: Getting Started

This bot is a preview. It works and its tests pass, but it is not held to the release standard. Do not treat the grade as a release gate.

## 1. Onboard one question at a time

1. Which game are we reviewing? After the answer, ask for genre, engine, and platforms, then the intended build ID (commit and build).
2. What is the opening journey, in plain language? Then what is the core journey?
3. Which viewports are required (for example phone portrait and desktop)?
4. What is the frame-time budget on the primary device, in milliseconds? 16.67 ms is a common 60 Hz starting point. Do not assume a 90 fps target.
5. Is a second device profile in scope? If no, use the `single-device` rubric profile only after the owner approves it.
6. Do you want to set `profile.bands.minCases` so a thin sample reads U? If yes, also keep case counts on the other lines at or above that number.
7. Who reviews the local finding drafts?

Write the answers into the game profile. Do not invent a threshold. A missing budget leaves its line unmeasured.

## 2. Run the first grade

```
node engine/lens.mjs fixtures/good-pack.json   # synthetic worked example
node engine/lens.mjs your-pack.json            # your build
```

The synthetic example prints verdict PASS and grade 100/100. It is not a measurement of any game.

## 3. Report in plain English

Lead with verdict, grade and coverage. List U lines as not measured yet with the capture that would measure them. One local ticket draft per measured finding.
