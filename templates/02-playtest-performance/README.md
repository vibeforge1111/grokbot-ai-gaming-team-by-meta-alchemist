## Start here

**What it does.** Grade playtest journeys and frame time for any game, then write a local evidence pack and ticket drafts.

**When to use it.** After a playable build can be clicked, tapped, or driven through its opening and a core session, and you want a first read of journeys and frame time.

**Setup.** The Grok Bot share link is coming soon, so there is no link to open yet. Paste each `SKILL.md` from `skills/` into a Grok Bot chat and say: "Save this as a skill." Save `playtest-performance-lens-engine` first, then `playtest-performance-getting-started`. Then save the rest: `autonomous-browser-playtest`, `frame-pacing-and-gpu-profiler`. Paste each fact in [MEMORY.md](MEMORY.md) and say: "Remember this for this project." The same files work in Claude, ChatGPT, Codex, Cursor, Gemini, or any other chat. See [INSTALL.md](../../INSTALL.md). Step by step: [HOW-TO-USE.md](HOW-TO-USE.md).

**First prompt.** Copy this into the chat after the skills are saved. Fill in the angle brackets.

```
Run the playtest-performance-getting-started skill. Ask me one question at a time. My game is <name or code name, genre, engine, platforms>. The build to grade is <commit and build id>. The opening journey is <plain description>. The core journey is <plain description>. Evidence comes from <playtest sessions, a CI run, a manual capture, or a browser script I already have>.
```

## Owner calls

- The opening and core journeys, in plain language for this game.
- The required viewports.
- The frame-time budget on the primary device. 16.67 ms is a common 60 Hz starting point. Do not assume a 90 fps target.
- Whether a second device profile is in scope. If it is not, use the `single-device` rubric profile.
- How many observed cases a journey or frame line needs (`profile.bands.minCases`). If you set this, also keep case counts on the other lines at or above that number, or those lines will read U.
- Who reviews the local ticket drafts.


## Team handoffs

Files are exchanged locally under `.grokbot-team/artifacts/<artifact-id>/` in your game project. Nothing is sent anywhere.

| Artifact | Direction | Required | Other end | If it is missing |
|---|---|---|---|---|
| `game-profile` | consumes | required | The owner, via the getting-started skill | Run the getting-started skill first; lines with no budget grade U |
| `feel-findings` | consumes | optional | Game Feel (01) | Continue without it. Start the report with "ASSUMPTION: no feel-findings available" |
| `loop-report` | consumes | optional | Game Loop (05) | Continue without it. Start the report with "ASSUMPTION: no loop-report available" |
| `hud-capture-set` | consumes | optional | HUD (09) | Continue without it. Capture the screen side of a journey yourself if you need it |
| `evidence-pack` | produces | optional | Other templates that grade a pack | They still accept a pack you assembled yourself |
| `grade-record` | produces | required | Producer (12), the owner | Nothing to compare next week; run the engine again |
| `ticket-draft` | produces | optional | Bug Desk (18), then the human files it | Findings stay in the report only |

This is a preview. Do not treat the grade as a release gate.
