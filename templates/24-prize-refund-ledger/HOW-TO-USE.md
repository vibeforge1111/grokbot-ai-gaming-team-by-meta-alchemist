## First run

Run the `prize-ledger-getting-started` skill. It asks one question at a time:

1. Which game, which build, and who produces the evidence pack?
2. Which prizes, entitlements and refund programs are in scope, and who approves exceptions?
3. What source proves fulfillment for each program (an entitlement read, a grant log, a refund receipt), and what is the wait limit?
4. Does this program grant account entitlements only, or does it pay to an address that needs a private address review? If it pays, what address format and mask lengths apply?

Then it checks the install and grades the synthetic worked example:

```sh
node tests/run-all.mjs
node engine/lens.mjs fixtures/good-pack.json
node ledger/scenario.mjs --digest
```

## Local input and review output

Use an owner-prepared JSON journal with packId, gitSha, liveSha, profile, nowMs, deadlineMs, rows and a snapshot of subjectKey and prizeKey pairs. Each row supplies id, prizeKey, subjectKey and history. subjectKey is the kit's salted subject id (sub_ plus 32 lowercase hex); row ids, prize keys and references are short opaque keys. History events carry to, role (agent, owner or evidence-import), at and, when required, a decisionRef or evidence with kind and ref.

You get an evidence pack and a local digest of held, proposed, reported and evidence-backed rows that names what needs the owner's decision. Nothing is granted, paid, refunded or sent.

Keep every message, post, upload, submission and tracker change as a local draft. Only the human reviews and sends, publishes, uploads or files it.

Work only on a working branch. Push only when the human asks and only to that branch. Never push to main. The human merges and deploys. Any feature switch you add is off by default.

Shared memory:

- Before acting, read `decisions`, `incidents`, `releases` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
