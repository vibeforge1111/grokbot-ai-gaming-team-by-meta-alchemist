# How to use: Game Clipmaker

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- Add worked examples from at least two real gameplay recordings. The current pack is a synthetic fixture, which is not enough.
- Grade a real recording and timecode log, not only the synthetic pack. `engine/build-pack.mjs` can write a pack and a producer receipt from owner-supplied files once those files exist.
- There is still no bundled encoder or highlight detector; bring your own tools. This bot never uploads. Trailer Director (10) still covers trailer-shaped cuts.

Grade peak-moment detection and a local clip list from gameplay recordings, then write ticket drafts. Trailer Director still covers trailer-shaped cuts; this bot finds in-match moments.

- **Pipeline stage:** Ship, Live.
- **When:** When you have gameplay recordings and want a first read of peak moments, timecodes, or a local clip list, rather than a trailer cut.
- **You provide:** Your game profile, gameplay recordings or a moment log with timecodes, and rights or source-build notes from files you already have.
- **You get:** A local clip list, a 100-point grade, and local ticket drafts. Nothing is uploaded until you upload it.
- **Takes from:** The owner's game profile, plus an optional evidence pack or HUD capture set when those already exist.
- **Hands to:** Trailer Director (10) or Studio Director (29) if they take the clip list further; Bug Desk (18) for ticket drafts; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option A: Add to Grok Bot after review

Share link coming soon. Use Option B for Grok Bot or Option C for other agents. Both work offline with the local files.

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." Start with the [`game-clipmaker-lens-engine`](skills/game-clipmaker-lens-engine/SKILL.md) skill, then the [`game-clipmaker-getting-started`](skills/game-clipmaker-getting-started/SKILL.md) skill, then `peak-moment-and-timecode-pass` and `clip-clarity-and-rights-check` and `clip-list-safety-and-identity`.
2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the game-clipmaker-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

### Option C: Other agents (Cursor, Claude Code, Codex)

Copy `skills/<name>/SKILL.md` into your agent's skills folder (for example `.cursor/skills/`, `.claude/skills/` or the folder your Codex setup reads). Copy `engine/` and `fixtures/` into your repo so the agent can run the engine, or let the agent write them from the `-lens-engine` skill. See [INSTALL.md](../../INSTALL.md).

## First real pack

1. Agree the profile with the getting-started skill, including clip length, the number of moments, and redaction rules.
2. Collect recordings or a moment log with timecodes, plus rights notes, with the evidence skills or the owner's tools.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own, or run `node engine/build-pack.mjs <intake> --out <dir>`.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

You can also stamp a pack and a receipt with `node engine/build-pack.mjs <intake-or-pack.json> --out <dir>`. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- Target clip length and how many peak moments to list.
- Which HUD or secret UI must be redacted.
- Who holds the rights to the recording.
- Who reviews the local drafts. The bot never uploads.

## Words used here

- **Peak moment:** a short in-match event worth clipping, such as a clutch, a near miss, or a turning point the owner cares about.
- **Timecode:** the start and end time in the source recording, in seconds or a clock format the owner already uses.
- **Redaction:** hiding HUD, chat, or other UI the owner does not want in a shared clip.

- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `evidence-pack` (optional, ^1.0.0) | the owner, 02 Playtest, 04 Netcode, 07 Shader, 08 World and Biome, 16 Splat Cleaner | the pack path the owner gives, or `.grokbot-team/artifacts/evidence-pack/` | Stop and ask the owner for a pack. Without one there is no grade; record NOT_RUN. |
| `hud-capture-set` (optional, ^1.0.0) | 09 HUD | `.grokbot-team/artifacts/hud-capture-set/` | Continue without it. Start the report with "ASSUMPTION: no hud-capture-set available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `clip-list` 1.0.0 | JSON clip list | `.grokbot-team/artifacts/clip-list/` | 19 Store Page, 20 Patch Notes, 29 Studio |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-30-game-clipmaker` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
