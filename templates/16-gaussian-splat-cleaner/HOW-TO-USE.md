# How to use: Gaussian Splat Cleaner

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- This template still needs evidence from a working splat cleanup on a real capture. The current pack is a synthetic fixture, which is not enough.
- Add worked examples from at least two real captures. Grade those captures, not only the synthetic pack. `engine/build-pack.mjs` can write a pack and a producer receipt once those files exist.
- There is still no bundled splat editor or cleaner; bring your own tools. The source capture must stay untouched.

Grade splat cleanup, continuity, and navigation proxies from owner-supplied captures, then write a local evidence pack and ticket drafts.

- **Pipeline stage:** Production.
- **When:** When you have a Gaussian splat or similar 3D capture to clean, and you want a first read of floaters, seams, budget, or walkable proxies.
- **You provide:** Your game profile, a before and after splat or capture, a cleanup report, and a proxy or nav report from tools you already have.
- **You get:** A local evidence pack, a 100-point grade, a change list, and local ticket drafts. Nothing is filed until you file it.
- **Takes from:** The owner's game profile, plus optional captures already stored as an evidence pack.
- **Hands to:** Other templates that read an evidence pack or a change list; Bug Desk (18) for ticket drafts; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option A: Add to Grok Bot after review

Share link coming soon. Use Option B for Grok Bot or Option C for other agents. Both work offline with the local files.

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." Start with the [`splat-cleaner-lens-engine`](skills/splat-cleaner-lens-engine/SKILL.md) skill, then the [`splat-cleaner-getting-started`](skills/splat-cleaner-getting-started/SKILL.md) skill, then `floater-and-seam-cleanup-review` and `splat-proxy-and-budget-check` and `splat-source-safety-and-identity`.
2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the splat-cleaner-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

## First real pack

1. Agree the profile with the getting-started skill, including budgets and whether a nav proxy is required.
2. Keep the source capture read-only. Run the owner's cleaner, and collect before and after files plus a cleanup report.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own, or run `node engine/build-pack.mjs <intake> --out <dir>`.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

You can also stamp a pack and a receipt with `node engine/build-pack.mjs <intake-or-pack.json> --out <dir>`. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- The floater or outlier rule, and the splat-count or memory budget.
- Whether a walkable proxy is required.
- Where the source capture is kept. This bot must not overwrite it.
- Who reviews the local drafts. The bot never files them.

## Words used here

- **Floater:** a splat or fragment that sits off the intended surface and should be removed or flagged.
- **Proxy:** a coarser mesh or volume used for navigation or collision, derived from the cleaned capture.
- **Source capture:** the original splat or scan. Cleanup writes a new file; the source stays untouched.

- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `evidence-pack` (optional, ^1.0.0) | the owner, 02 Playtest, 04 Netcode, 07 Shader, 08 World and Biome | the pack path the owner gives, or `.grokbot-team/artifacts/evidence-pack/` | Stop and ask the owner for a pack. Without one there is no grade; record NOT_RUN. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `evidence-pack` 1.0.0 | JSON evidence pack plus a local manifest | `.grokbot-team/artifacts/evidence-pack/` | 01 Game Feel, 03 Prop and Rig, 05 Game Loop, 06 Economy, 07 Shader, 09 HUD, 10 Trailer, 11 Environment, 12 Producer, 13 Audio, 14 NPC and Lore, 15 Server Fairness, 17 Sprites, 18 Bug Desk, 19 Store Page, 20 Patch Notes, 21 Access, 22 Live Service, 23 Support Desk, 24 Ledger, 25 Matchmaking, 26 Balance Patch, 27 Retention, 28 App Store, 30 Clipmaker, 00 Starter |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `change-list` 1.0.0 | JSON change list | `.grokbot-team/artifacts/change-list/` | 06 Economy, 10 Trailer, 20 Patch Notes |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-16-gaussian-splat-cleaner` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
