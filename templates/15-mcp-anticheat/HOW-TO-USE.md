# How to use: Server Fairness & Anti-Cheat Guard

Created by @meta_alchemist (https://x.com/meta_alchemist).

For games with a server, compare scene data across engines and review whether the server enforces your game's rules fairly.

Two parts: the Scene Parity part (`cross-editor-scene-parity`) proves the server's level data match what players see after an editor export or an agent edit over MCP (Model Context Protocol); the Anti-Cheat Guard part (`server-authority-fairness-audit`) reviews that your own server enforces your game's rules. A fully offline game has nothing to review here.

- **Pipeline stage:** Production, Live
- **Fits:** any game with a server or host that decides outcomes: online arena or racing games, co-op sims, online card or turn-based strategy games, server-checked leaderboards.
- **When:** Before ranked play, tournaments or prize events, after a level moves between editors, and after cheating reports.
- **You provide:** Server decision logs from a local or staging server you authorize, the rules the server enforces (its authority model), and scene exports from each editor.
- **You get:** Findings on server authority and fairness (`fairness-findings`), a list of authority gaps as local ticket drafts, and a human review queue draft of suspected multi-account groups (never automatic bans).
- **Takes from:** your own server tests and player reports (an `evidence-pack`), and the approved `game-profile`.
- **Hands to:** Bug Desk (18) for local ticket drafts, and Live Service, Payments and Trust (22) for a draft enforcement policy (`enforcement-policy-draft`) that a human approves.

Use a CI run or a manual capture for build evidence. Playtest QA (template 02) is coming later.

## Rubric

`gbf-15-mcp-anticheat-director` v1.3.0, 100 points: 5 pillars of 20, 2 lines each, levels 0 to 4 or U. Full table: [RUBRIC.md](RUBRIC.md).

| Line | Name | Weight | Evidence | Needs |
|---|---|---|---|---|
| `server-authority:1` | Server decides every action and reward (for example moves, turns, hits, scores, rewards) | 10 | trace | any server game |
| `server-authority:2` | Input validation and clamping | 10 | trace | any server game |
| `cadence-and-timing:1` | Action rate and cooldown enforcement | 10 | trace | any server game (any action rate limit) |
| `cadence-and-timing:2` | Lag compensation window integrity (only for real-time hit judging) | 10 | trace | real-time hit judging |
| `parity:1` | Same action rules for humans, bots and scripted input | 10 | trace | bots or scripted input |
| `parity:2` | Input assist parity across devices (only with input assists) | 10 | trace | input assists on two or more devices |
| `exposure-and-abuse:1` | Hidden information stays hidden | 10 | trace | level geometry (scene receipts) |
| `exposure-and-abuse:2` | Flooding, malformed packets, connection abuse | 10 | trace | any server game |
| `recovery-and-detection:1` | Reconnect and duplicate-join handling | 10 | trace | any game with sessions |
| `recovery-and-detection:2` | Score and reward integrity, detection and review | 10 | trace | an automatic detector |

Two approved profiles mark a line not applicable: `turn-based` (`cadence-and-timing:2`) and `no-input-assist` (`parity:2`). The owner approves them before scoring and sets `rubricProfile` in the game profile. The line then reads N/A, its partner line takes the pillar's 20 points, and the verdict can reach PASS (see [docs/RUBRIC_GUIDE.md](../../docs/RUBRIC_GUIDE.md#applicability)). The other lines that need a feature (bots or scripted input, level geometry, sessions, an automatic detector) have no profile: when the game lacks it, the line stays U (unmeasured), is reported as "does not apply", and the verdict stays CONDITIONAL.

## Decisions only you make

- If your game has an automatic cheat detector, how many honest sessions may it wrongly flag, and how many known-cheat test sessions may it miss?
- If your game judges hits in real time, how far back may the server rewind time to judge a hit?
- If your game has input assists, how strong should each be per device, and how much difference between devices is acceptable?
- Which rubric profiles apply (`turn-based`, `no-input-assist`), approved before scoring and set as `rubricProfile` in the game profile.
- Every enforcement decision about a player. The bot only drafts review-queue entries.

## Known limits

- Detection rates need labelled sessions; the worked example is synthetic.

## Safety defaults

- Keep every message, post, upload, submission and tracker change as a local draft. Only the human reviews and sends, publishes, uploads or files it. Work only on a working branch. Push only when the human asks and only to that branch. Never push to main. The human merges and deploys. Any feature switch you add is off by default.
- Missing evidence grades U (unmeasured), never a made-up number. Worked examples are labelled synthetic.
- Defensive only: tests run on your own local or staging server with your written go-ahead, never against live players, live servers or other games. The bot never writes cheats and never bans, mutes or contacts a player. Player identifiers stay out of reports.
- Thresholds live in your game profile (`pack.profile`), never inside the engine.
