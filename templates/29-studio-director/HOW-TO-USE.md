# How to use: Studio Director

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- Add worked examples from at least two real shoots or stills sequences. The current pack is a synthetic fixture, which is not enough.
- Grade a real shot list and continuity notes from a project, not only the synthetic pack. `engine/build-pack.mjs` can write a pack and a producer receipt from owner-supplied files once those files exist.
- There is still no bundled editor or renderer; bring your own tools. This bot never publishes or uploads.

Grade cinematic continuity, shot coverage, and a local export plan for any game, then write a work plan and ticket drafts. Trailer Director still covers trailer cuts; this bot plans the shoot or stills sequence.

- **Pipeline stage:** Ship, Production.
- **When:** When you are planning a cinematic, a stills sequence, or a shoot, and you want a first read of continuity, coverage, or a local export plan.
- **You provide:** Your game profile, a shot or stills list, continuity notes, and rights or clearance notes from files you already have. An optional clip list from Trailer Director (10) or Game Clipmaker (30) can sit beside those files.
- **You get:** A local work plan, a media export manifest, a 100-point grade, and local ticket drafts. Nothing is published until you publish it.
- **Takes from:** The owner's game profile, plus an optional clip list from Trailer Director (10) or Game Clipmaker (30), and an optional pitch draft.
- **Hands to:** Trailer Director (10) or Game Clipmaker (30) if they take the work plan or clip list further; Bug Desk (18) for ticket drafts; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option A: Add to Grok Bot after review

Share link coming soon. Use Option B for Grok Bot or Option C for other agents. Both work offline with the local files.

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." Start with the [`studio-director-lens-engine`](skills/studio-director-lens-engine/SKILL.md) skill, then the [`studio-director-getting-started`](skills/studio-director-getting-started/SKILL.md) skill, then `continuity-and-coverage-board` and `runtime-and-rights-check` and `studio-export-plan-and-safety`.
2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the studio-director-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

### Option C: Other agents (Cursor, Claude Code, Codex)

Copy `skills/<name>/SKILL.md` into your agent's skills folder (for example `.cursor/skills/`, `.claude/skills/` or the folder your Codex setup reads). ## First real pack

1. Agree the profile with the getting-started skill, including runtime, required beats, and who reviews drafts.
2. Collect a shot or stills list, continuity notes, and rights notes with the evidence skills or the owner's tools.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own, or run `node engine/build-pack.mjs <intake> --out <dir>`.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

You can also stamp a pack and a receipt with `node engine/build-pack.mjs <intake-or-pack.json> --out <dir>`. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- Target runtime and required story beats.
- Which characters and locations need continuity checks.
- Who signs off rights and clearance.
- Who reviews the local drafts. The bot never publishes or uploads.

## Words used here

- **Continuity:** whether character, location, and time stay consistent across planned shots or stills.
- **Coverage:** whether every required story beat has at least one planned shot or still.
- **Export plan:** a local list of shots or stills to export, with names and target formats. Nothing is uploaded until a person does it.

- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `clip-list` (optional, ^1.0.0) | 10 Trailer, 30 Clipmaker | `.grokbot-team/artifacts/clip-list/` | Continue without it. Start the report with "ASSUMPTION: no clip-list available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |
| `pitch-draft` (optional, ^1.0.0) | 12 Producer | `.grokbot-team/artifacts/pitch-draft/` | Continue without it. Start the report with "ASSUMPTION: no pitch-draft available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `work-plan` 1.0.0 | JSON work plan | `.grokbot-team/artifacts/work-plan/` | 20 Patch Notes |
| `media-export-manifest` 1.0.0 | JSON manifest plus the exported video and still files | `.grokbot-team/artifacts/media-export-manifest/` | 19 Store Page, 20 Patch Notes |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-29-studio-director` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
