## Option C: other agents

Use [SYSTEM_PROMPT.md](SYSTEM_PROMPT.md) as the system prompt, and give the agent MEMORY.md, PROMPTS.md and the `skills/` folder. Run every command from this template folder with Node 18 or later.

## First run

Run the `store-submission-getting-started` skill. It asks one question at a time:

1. Which game, which build, and who produces the evidence pack?
2. Which store or distribution target and which build are being prepared?
3. Which current policy references and requirements apply to that target (the check ids per group)?
4. Who owns signing, listing materials, account decisions and the final submission?

Then it checks the install and grades the synthetic worked example:

```sh
node tests/run-all.mjs
node engine/lens.mjs fixtures/good-pack.json
node mobile/run.mjs --report
```

## Local input and review output

For any target supply packId, gitSha, liveSha, profile.requirements and checks. Define required check IDs under config, hard, perm, privacy, billing, accounts, secrets, signing and listing. A check has group, id, build, source and a boolean passed. Use references to sanitized evidence. Never supply signing material.

You get an evidence pack and a local checklist sorted by severity with the evidence line and the fix for each check, plus the owner questions. Nothing is built, signed, uploaded or submitted.

Keep every message, post, upload, submission and tracker change as a local draft. Only the human reviews and sends, publishes, uploads or files it.

Work only on a working branch. Push only when the human asks and only to that branch. Never push to main. The human merges and deploys. Any feature switch you add is off by default.

Shared memory:

- Before acting, read `decisions`, `entitlements`, `incidents` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`, `releases`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-28-mobile-store-submission` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
