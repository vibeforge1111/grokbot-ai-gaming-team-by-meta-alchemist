# How to use: Procedural World and Biome Architect

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- Add worked examples from at least two real seeded worlds. The current pack is a synthetic fixture, which is not enough.
- Grade exports and traversal reports from a real project, not only the synthetic pack. `engine/build-pack.mjs` can write a pack and a producer receipt from owner-supplied exports once those files exist.
- There is still no bundled world generator or navmesh tool; bring your own tools.

Grade seeded world generation, traversal, and encounter placement for any engine, then write a local evidence pack and ticket drafts.

- **Pipeline stage:** Production.
- **When:** When a seeded world or biome generator exists, and you want a first read of repeatability, traversal, or encounter placement.
- **You provide:** Your game profile, two or more seeded exports, a nav or traversal report, and an encounter-density report from tools you already have.
- **You get:** A local evidence pack, a 100-point grade, a layout brief, and local ticket drafts. Nothing is filed until you file it.
- **Takes from:** The owner's game profile, plus an optional layout brief from Environment Design (11) when that bot has already run.
- **Hands to:** Environment Design (11) if you share a layout brief; other templates that read an evidence pack; Bug Desk (18) for ticket drafts; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option A: Add to Grok Bot after review

Share link coming soon. Use Option B for Grok Bot or Option C for other agents. Both work offline with the local files.

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." Start with the [`world-biome-lens-engine`](skills/world-biome-lens-engine/SKILL.md) skill, then the [`world-biome-getting-started`](skills/world-biome-getting-started/SKILL.md) skill, then `seeded-world-repeatability-check` and `traversal-and-cover-audit` and `encounter-placement-and-world-safety`.
2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the world-biome-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

### Option C: Other agents (Cursor, Claude Code, Codex)

Copy `skills/<name>/SKILL.md` into your agent's skills folder (for example `.cursor/skills/`, `.claude/skills/` or the folder your Codex setup reads). Copy `engine/` and `fixtures/` into your repo so the agent can run the engine, or let the agent write them from the `-lens-engine` skill. See [INSTALL.md](../../INSTALL.md).

## First real pack

1. Agree the profile with the getting-started skill, including seeds, traversal checks, and encounter density.
2. Export at least two seeds, plus a traversal report and an encounter report, with the evidence skills or the owner's tools.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own, or run `node engine/build-pack.mjs <intake> --out <dir>`.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

You can also stamp a pack and a receipt with `node engine/build-pack.mjs <intake-or-pack.json> --out <dir>`. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- Which seeds are known, and which seed is held out.
- What a walkable route means in this game.
- The acceptable encounter density range.
- Who reviews the local drafts. The bot never files them.

## Words used here

- **Seed:** the value that must reproduce the same world when generation runs again on the same build.
- **Held-out seed:** a seed kept back from tuning, then run to check that the world still holds.
- **Encounter density:** how many encounters appear per agreed unit of space or time, compared with the owner's range.

- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `layout-brief` (optional, ^1.0.0) | 11 Environment | `.grokbot-team/artifacts/layout-brief/` | Continue without it. Start the report with "ASSUMPTION: no layout-brief available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `evidence-pack` 1.0.0 | JSON evidence pack plus a local manifest | `.grokbot-team/artifacts/evidence-pack/` | 01 Game Feel, 03 Prop and Rig, 05 Game Loop, 06 Economy, 07 Shader, 09 HUD, 10 Trailer, 11 Environment, 12 Producer, 13 Audio, 14 NPC and Lore, 15 Server Fairness, 16 Splat Cleaner, 17 Sprites, 18 Bug Desk, 19 Store Page, 20 Patch Notes, 21 Access, 22 Live Service, 23 Support Desk, 24 Ledger, 25 Matchmaking, 26 Balance Patch, 27 Retention, 28 App Store, 30 Clipmaker, 00 Starter |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `layout-brief` 1.0.0 | JSON layout brief | `.grokbot-team/artifacts/layout-brief/` | 03 Prop and Rig, 15 Server Fairness |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-08-world-biome` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
