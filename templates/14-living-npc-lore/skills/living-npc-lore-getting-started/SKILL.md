# Living AI NPC and Lore Architect: getting started

Design what an NPC can remember, how it responds and which version of a world fact it may reveal, then audit those decisions against scoped transcripts and traces. An NPC is any non-player character: a shopkeeper, a guide, a rival, a companion, a witness. It works for hand-written dialogue trees and for generated (AI) dialogue, and for any response channel: spoken or written lines, a reply menu, a gesture or a sound.

A line with fewer observed cases than `profile.bands.minCases` reads U, even if those cases would have passed. Ask the owner to set this number. If it is not set yet, write "not set" and tell them that thin lines are provisional until they set it. For generated dialogue, run each probe at least that many times.

If `engine/lens.mjs` is not on disk, write the files from the `living-npc-lore-lens-engine` skill first (Node 18 or later, no dependencies). If `fixtures/scene-book.md` is missing, write it from the "Worked example files" section of the `npc-replay-panel` skill.

## Words used here

- **Canon:** the owner's approved world facts, with a revision label (`canonRevision`).
- **Scope of a pack:** one NPC role, one canon revision, one response channel, one replay seed and one held-out scenario.
- **Response key:** a short code for what a response means, so different wordings with the same meaning match.
- **Viewpoint:** what this character could know from where it was. A belief, rumor or lie is allowed only with an approved exception.
- **Reveal gate:** the event or state before which a canon fact must not be said.
- **Seeded replay and held-out scenario:** the same scene run twice from the same seed; and a scene reserved before tuning, read back by a reviewer.
- **U (UNMEASURED) and NOT_RUN:** U means no usable evidence yet; it earns 0 points and is not a defect. NOT_RUN means a planned run did not happen.

## 1. Onboard one question at a time

Start with the game, the NPC role and the scene or canon change under review. Ask one question, wait for the answer, then ask the next. Never stack questions in one message. If the owner does not know an answer yet, write "not set" and move on: the lines that need it grade U until it is set. Write each answer into a draft game profile, using the profile in `fixtures/good-pack.json` as the shape. Its values are synthetic examples, never defaults.

1. "Which game are we working on? Tell me its name or a code name, its genre, engine and platforms."
2. "Which NPC role are we checking, and which scene or canon change is under review? For example a shopkeeper's new festival lines, or a guide after a lore rewrite." (`role`)
3. "Is this NPC's dialogue hand-written, generated by a model, or both?"
4. "Which build should I look at? Give me the source revision and the build testers or players run." (`gitSha`, `liveSha`)
5. "What may this NPC observe? For example only what happens in its shop, or everything within earshot."
6. "What should it remember, and where must it forget? For example until the chapter closes, the season ends or a save is reloaded. If it remembers nothing between scenes, say so and the memory lines will show as does not apply." (`memoryBoundary`)
7. "Which canon revision is active, and which source wins when two disagree?" (`canonRevision`)
8. "Which facts are gated, and what must happen before the NPC may say them? If there are no gates, say so." (`revealGate`)
9. "How does the NPC respond in this pack: spoken lines, text, a reply menu, gestures or sounds? Pick one channel; each further channel is its own pack." (`responseChannel`)
10. "Which seed should a known scene replay from? Pick one; each further seed is its own pack." (`scenarioSeed`)
11. "Which scene have you held out, unseen and untuned, for a reviewer to read back? Pick one; each further held-out scenario is its own pack." (`heldOut`)
12. "What share of cases should count as the floor, the pass and the target? For example 0.5, 0.75 and 1." (`bands`)
13. "How many observed cases must a line have before a share is scored? If it has fewer, that line reads U. For example 3. For generated dialogue, use at least that many runs of each probe." (`bands.minCases`)
14. "Where should I save local drafts (memory policy, dialogue drafts, canon diffs, ticket drafts), and who reviews them before anything is filed or sent?"

Then choose a scope name for this profile revision (for example `shopkeeper-canon-b-text`). In short: the profile holds the response channel, replay seed and held-out scenario for this pack. Grade each further channel, seed or held-out scenario as its own pack and scope.

## 3. Collect and grade a real pack

Ask for a versioned canon excerpt, the role's knowledge and memory rules, seeded case traces, dialogue captures and independent readbacks of the held-out scenario. Gather the rows with the evidence skills:

| Group | Line | Row fields | Skill |
|---|---|---|---|
| `recall` | `memory:1` | `{caseId, expected, recalled}` | `npc-memory-boundaries` |
| `expiry` | `memory:2` | `{caseId, forgotten}` | `npc-memory-boundaries` |
| `knowledge` | `viewpoint:1` | `{caseId, withheld}` | `npc-viewpoint` |
| `belief` | `viewpoint:2` | `{caseId, expected, asserted}` | `npc-viewpoint` |
| `intent` | `dialogue:1` | `{caseId, expected, actual}` | `npc-dialogue-repair` |
| `repair` | `dialogue:2` | `{caseId, expected, actual}` | `npc-dialogue-repair` |
| `version` | `canon:1` | `{caseId, expected, claim}` | `canon-reconciliation` |
| `reveal` | `canon:2` | `{caseId, legal}` | `canon-reconciliation` |
| `replay` | `review:1` | `{caseId, first, second, firstRef, secondRef, seed}` | `npc-replay-panel` |
| `heldout` | `review:2` | `{caseId, expected, readback, reviewRole, turnRef, reason, scenario, channel}` | `npc-replay-panel` |

Each group names its receipt in `artifact`. The receipt carries the line id, both build ids, the profile scope, a `context` with the profile's `role`, `canonRevision`, `responseChannel`, `heldOut` and `scenarioSeed`, and a `source` path with a turn locator. For a real pack set `synthetic` to false and follow "First real pack" in `HOW-TO-USE.md`. A pack without `gitSha`, `liveSha` or `packId` is INVALID. Then run `node engine/lens.mjs <pack.json>`.

If several kit templates work on this game, read the owner's earlier decisions first with `node engine/team-memory.mjs read decisions` from the game project root, so you do not ask again. Save the engine output as a local `grade-record` (for example under `.grokbot-team/artifacts/grade-record/<pack id>.json`) for Producer (12), which can use it as a milestone gate. Save dialogue revisions, memory policy notes and canon exceptions as a local `dialogue-draft` (under `.grokbot-team/artifacts/dialogue-draft/`) for Audio Director (13) and Access, Input and Localization (21).

## 4. Report in plain English

- Lead with the verdict, grade and coverage in one sentence. Say how many cases each measured line rests on.
- List U lines as "not measured yet" with the capture that would measure them. For a line that does not apply to this NPC, say so instead. Never call a U line a defect.
- One local ticket draft per measured finding, with the pack id and artifact ids. A fact kept after reset, a hidden fact disclosed or an early reveal is a P0 candidate for Bug Desk (18).
- Hand the narrative lead a local memory policy, branching dialogue draft, canon exception list and replay report.
- Label any synthetic pack as synthetic.

## 5. Skills in this template

- `npc-memory-boundaries`: remember a witnessed event; forget it at the reset point. Feeds `memory:1` and `memory:2`.
- `npc-viewpoint`: keep unseen facts private, with adversarial probes for generated NPCs; tie beliefs to their source. Feeds `viewpoint:1` and `viewpoint:2`.
- `npc-dialogue-repair`: convey the current intent and recover from unmatched input. Feeds `dialogue:1` and `dialogue:2`.
- `canon-reconciliation`: claims match the active canon; reveals wait for their gate. Feeds `canon:1` and `canon:2`.
- `npc-replay-panel`: seeded replay and held-out readback, plus the worked example scene book. Feeds `review:1` and `review:2`.
- `living-npc-lore-lens-engine`: the engine source and how to run it.
