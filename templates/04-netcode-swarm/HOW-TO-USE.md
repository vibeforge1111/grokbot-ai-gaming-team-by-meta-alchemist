# How to use: Multiplayer Netcode and Bot-Swarm Director

Created by @meta_alchemist (https://x.com/meta_alchemist).

**Status: preview, not shipping.** This template works and its tests pass, but it is not yet held to the kit's release standard.

Before it can ship:

- Add worked examples from at least two real multiplayer games. The current pack is a synthetic fixture, which is not enough.
- Grade a live session trace or soak log from a build, not only the synthetic pack. `engine/build-pack.mjs` can write a pack and a producer receipt from owner-supplied traces once those files exist.
- There is still no bundled headless bot runner or netcode sampler; bring your own capture tools.

Grade prediction, authority, desync, and bot-swarm load for any multiplayer game, then write a local evidence pack and ticket drafts.

- **Pipeline stage:** Production, Playtest.
- **When:** When a multiplayer build can be joined, and you want a first read of prediction, authority, desync, or bot-swarm load.
- **You provide:** Your game profile, session traces with predicted versus confirmed state, a desync log, and a bot-swarm or soak report from tools you already have.
- **You get:** A local evidence pack, a 100-point grade, and local ticket drafts. Nothing is filed until you file it.
- **Takes from:** The owner's game profile, plus an optional fairness-findings file from Server Fairness (15) when that bot has already run.
- **Hands to:** Other templates that read an evidence pack; Bug Desk (18) for ticket drafts; Server Fairness (15) if you reuse the same pack; Producer (12) if you use the grade as a milestone note. See Team handoffs in [README.md](README.md#team-handoffs).

This is a preview. Do not treat the grade as a release gate.

## Install

### Option B: Manual setup in Grok Bot

1. For each folder in `skills/`, paste its `SKILL.md` into a Grok Bot chat and say: "Save this as a skill." 2. Paste each fact from [MEMORY.md](MEMORY.md) and say: "Remember this for this project."
3. When the owner picks a cadence, create the routine from section 2 of [PROMPTS.md](PROMPTS.md): "Create a routine with this prompt: ...". Replace `<cadence>` first.
4. Say: "Run the netcode-swarm-getting-started skill." It grades the synthetic example first, then helps you collect a real pack.

## First real pack

1. Agree the profile with the getting-started skill, including the prediction budget, the authority list, and the soak target.
2. Collect session traces, a desync log, and a swarm or soak report with the evidence skills, or with the owner's own tools. Keep each source file on disk under the pack's folder.
3. Copy the shape of `fixtures/good-pack.json`, set `synthetic` to false, and replace every value with your own, or run `node engine/build-pack.mjs <intake> --out <dir>`.
4. Run `node engine/lens.mjs your-pack.json`. Lead with verdict, grade and coverage.

You can also stamp a pack and a receipt with `node engine/build-pack.mjs <intake-or-pack.json> --out <dir>`. Keep the worked examples labelled synthetic. Never copy a synthetic row into a real pack.

## Decisions only you make

- The prediction error budget, in milliseconds.
- Which events the server must own.
- Soak length and the acceptable desync rate.
- Bot count and whether bots may ever be counted as real players.
- Who reviews the local drafts. The bot never files them.

## Words used here

- **Prediction error:** the gap, in milliseconds, between a predicted state and the confirmed state for the same tick.
- **Authority:** whether a scored or valuable event is decided by the server, not by a client claim.
- **Swarm:** scripted bots used to load a session. They must be flagged as bots and never counted as players.

- **U:** unmeasured. The line earns 0 points and is not a defect.

## Works with other templates

This template works on its own. When other templates from the kit run in the same game project, they exchange files under `.grokbot-team/artifacts/<artifact>/` (read the newest file) and share an append-only memory under `.grokbot-team/memory/`. Team spec 1.0.0.

Before acting, look for these inputs:

| Input | From | Where to look | If it is missing |
|---|---|---|---|
| `game-profile` (required, ^1.0.0) | the owner | `pack.profile` in the evidence pack, or `.grokbot-team/artifacts/game-profile/` | Ask the getting-started questions and write it with the owner. A missing threshold leaves its line unmeasured, never a default. |
| `fairness-findings` (optional, ^1.0.0) | 15 Server Fairness | `.grokbot-team/artifacts/fairness-findings/` | Continue without it. Start the report with "ASSUMPTION: no fairness-findings available" and say which checks it would have informed. Leave lines that need it unmeasured. Never invent the missing data. |

After acting, save these outputs as local files for the human to review:

| Output | Format | Where | Read by |
|---|---|---|---|
| `evidence-pack` 1.0.0 | JSON evidence pack plus a local manifest | `.grokbot-team/artifacts/evidence-pack/` | 01 Game Feel, 03 Prop and Rig, 05 Game Loop, 06 Economy, 07 Shader, 09 HUD, 10 Trailer, 11 Environment, 12 Producer, 13 Audio, 14 NPC and Lore, 15 Server Fairness, 16 Splat Cleaner, 17 Sprites, 18 Bug Desk, 19 Store Page, 20 Patch Notes, 21 Access, 22 Live Service, 23 Support Desk, 24 Ledger, 25 Matchmaking, 26 Balance Patch, 27 Retention, 28 App Store, 30 Clipmaker, 00 Starter |
| `grade-record` 1.0.0 | JSON (the engine's grade record) | `.grokbot-team/artifacts/grade-record/` | 12 Producer |
| `ticket-draft` 1.0.0 | JSON or Markdown local draft | `.grokbot-team/artifacts/ticket-draft/` | 12 Producer, 18 Bug Desk |

Each output file is JSON with `artifact`, `version`, `producer` (this template's id and version), `createdAt` (UTC), `synthetic` and `items`, as the kit's `spec/artifacts/<artifact>.schema.json` describes. Name files `<UTC date>-<short label>.json` so the newest sorts last.

Shared memory:

- Before acting, read `decisions` from `.grokbot-team/memory/<topic>.jsonl`. Skip records that have expired or that a later record supersedes.
- Write only `decisions`. Append one line per record with `engine/team-memory.mjs` (or the same JSON by hand): id, UTC time, writer (`gbf-04-netcode-swarm` and `0.1.0`), topic, kind, summary, data, source, confidence (measured, reported or assumed), expires_at and supersedes. Never edit or delete a line; supersede it.
- Never put secrets, names, handles, wallets, emails or raw user ids in memory. Refer to a person or account only by `node engine/team-memory.mjs hash <id>`, which needs the salt in `GROKBOT_TEAM_SALT`. Run `node engine/team-memory.mjs lint` before you finish.
- Keep `.grokbot-team/` out of a public game repository (add it to `.gitignore`); in a private one, commit it so the append-only rule can be checked against history.
